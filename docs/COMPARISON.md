## Bugs / known limitations (v0.4)

| Severity | Issue |
|---|---|
| P3 | **The undo BAR is still single-slot (R2-N5 residual).** The bar holds one pending undo for 6 seconds — but it is no longer the only safety net: every delete of all six entity types also lands in the persisted Trash screen, so a missed undo window is recoverable. R2-N5 is closed as scoped in v0.4; this row tracks only the bar itself. |
| P3 | **Trash-screen restore of a single entity restores the entity only (R4-N2, new).** Links that the delete cleaned on OTHER entities are not re-linked when restoring from the Trash screen (the undo-bar path does re-link them via the Store link APIs; cascade restores — channels/pages — restore survivor links fully). A script restored from Trash can therefore hold one-way link fields until the other side is re-linked manually. Documented Store single-restore semantics, inherited from Round 3. |
| P3 | **Template delete has no undo and no trash entry (R4-N3, new, builder-disclosed).** Guarded by a confirmation dialog instead; the source page a template was snapshotted from is unaffected. |
| P3 | **UI import "has GhostBlade data" guard still checks only the four original keys (R4-N4, new).** A file containing ONLY templates/trash (or only pages/blocks) is rejected by the UI guard even though the Store would load it. The per-key TYPE validation now covers all eight keys in both layers (R3-N4 closed); this is the same class of consistency nit in the neighbouring guard, and the failure direction is safe (reject, never wipe). |
| P3 | **A second `catch (Throwable)` exists (R4-N1, new).** `registerPredictiveBackCallback()` catches Throwable around the API 33+ back-callback registration and falls back to the legacy override. Monitoring judges this justified (framework registration failure fallback, flag-scoped, disclosed) — it is not hiding app-logic bugs; the only other Throwable catch remains Store.emit's sink swallow. Recorded so the "one Throwable catch" statement from earlier rounds is not repeated unqualified. |
| P3 | **Single-Activity view switching keeps no per-screen scroll state**; returning to a list re-renders it from the top. |
| P3 | **Tasks have no reminders, recurrence, or priorities** — GhostBlade Task's Must-task engine is not integrated yet (planned combined-app phase). |
| P3 | **Launcher icon is inherited** from GhostBlade Task; no bespoke GhostBlade Notion icon yet. |
| P3 | Carried minor items (Monitoring R2/R3): no Unlink button on the script screen's task list, `persistenceAvailable` flag written but never read, `Logic.addDays()` throws on invalid input (latent, no UI caller). |

**Resolved in v0.4 (Round 3 list):** no page reparent/move UI (R3-N1 — "Move to…" picker in the page menu + page screen calls the tested Store.movePage, excludes self + descendants, current parent excluded, rejection surfaced as a toast); toggle child blocks not creatable in the UI (R3-N2 — Store.addBlock gained a validated parentBlockId parameter; toggle ⋯ menu "＋ Add child block" authors children, rendered via Store.childBlocks); block move on the page-global order (R3-N3 — Store.moveBlock/Up/Down are now sibling-scoped: a move repositions only within the same-parent subsequence, other groups keep their slots, orders normalised; block undo stores the sibling index); UI import key list omits "pages" (R3-N4 — the UI knownKeys list is now all eight keys the Store validates, incl. templates/trash); the R2-N1 emit-flush exception (Store.linkIdeaToScript/unlinkIdeaFromScript added; both performUndo relink sites call it; MainActivity now contains ZERO direct assignments to linkedScriptId/linkedIdeaId — "no UI direct mutation" is absolute); single-slot memory-only undo with no trash (R2-N5, closed as scoped — persisted Trash: all six delete flows route through the ToTrash APIs with the Round 3 paths as fallback, Trash screen with restore/permanent-delete/empty, trash persists across JSON round-trip and inside export/import, undo bar rides on restoreFromTrash); deprecated onBackPressed (N-10 — back logic extracted to handleBack(); API 33+ uses a registered OnBackInvokedCallback, the deprecated override remains only as the API <33 fallback with a double-handling guard; the one remaining deprecation warning is the unavoidable super.onBackPressed() call inside that fallback).

**Resolved in v0.3 (Round 2 list):** channel-delete orphans (R2-P2-1 — decided cascade policy: the delete dialog discloses the script/task/idea counts, `Store.removeChannelCascade` cascades and cleans survivor links, Undo restores channel + contents + links fully via `restoreChannelCascade`); Db mirror divergence on UI mutations (R2-N1 — Store remove/rename/update APIs for all six entity types emit to the sink, deletes emit tombstones, imports tombstone ghost rows, and no UI direct-mutation path remains except the one documented emit-flushed idea↔script undo relink); import type-blindness (R2-N4 — per-key array validation in UI + Store Boolean); script channel move bypass (updateScript gained a validated `channelId` parameter; the last direct `script.channelId =` site is deleted); edit-draft restore condition (R2-N6); per-script draft cleanup on delete (R2-N7); dead `pickScript()` removed (R2-N9).

**Resolved in v0.2 (Round 1 list):** Db honesty (write-through mirror, JSON authoritative, wording corrected); script body editing routed through `Store.updateScript` (bumps `updatedAt`); user-facing JSON export/import; search; language chips with persistent selected state; channel picker + date picker in editors; delete/rename with undo for all four entity types; tappable bidirectional idea↔script links; editor draft autosave across process kill; `android:allowBackup="false"`; COMPARISON counts mechanically corrected; build is byte-reproducible (stable SHA-256 across clean builds).

No P1 (crash/data-loss) bugs are known in v0.4 and no P2s are open: Monitoring's sweep found all force-unwraps guarded (5 `!!` sites: the two script `date!!` behind isNullOrBlank checks, the two draft `!!` behind restored-draft booleans, and Logic's date comparator `a!!/b!!` behind its both-non-blank guard) and the new paths (table/board rendering, templates, trash-backed deletes + restores, page move, child blocks, back-callback dispatch) null-safe and Store-routed.
